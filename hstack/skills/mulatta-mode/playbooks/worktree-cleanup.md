### Worktree cleanup

1. Snapshot and audit. Record `df -h /`, then run `scripts/worktree-audit.sh [-b <pr-base-ref>] [repo-path]` (principle-build-the-lever). Without `-b` it checks `MERGED` against `origin/HEAD`, so pass `-b origin/<branch>` when PRs target another branch. It reads paths from `git worktree list`, never hand-typed: worktrees live under `<repo>__worktrees/`, `~/.herdr/worktrees/<repo>/`, a scratchpad, and `~/.claude/outputs/`, and a hand-typed set misses whole directories.
2. The buckets are advice, not permission. `LIVE` comes from an agent terminal whose cwd is in the worktree and is the strongest signal; a `hold-in-use` row is not a candidate. A worktree on a detached HEAD reads `MERGED=no`, `no-remote`, and `PR=-` whether or not its work landed. Check the commit or the PR yourself before calling such a row stale.
3. `LAST_SESSION` is a date only when a session's cwd was that worktree. A `~` prefix means a transcript merely mentioned the path, which an audit or a report that printed the list also does, so it is a reason to look rather than evidence of use. For a `verify-recent-session` row, or anything you doubt, read that session: a subagent reports whether the work is ongoing and which worktrees it touches, and the transcript stays in the subagent (principle-guard-the-context-window).
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits. Show the diff and get a decision first, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. `scratch:N` is untracked throwaway, safe to drop, but name the files. Clean, landed, and not in use proceeds; `wip` and in-use pause.
5. Prune the confirmed set. Per path, `git worktree remove --force <path>`. If the dir survives on ignored build artifacts, `rm -rf` it, then `git worktree prune`. Branch refs survive, so no commits are lost. Confirm with `df -h /` and re-list.
6. Other reclaimers are reported, not run. Name what each would free and let the user decide: old build artifacts in the worktrees that remain, and the session scratchpads. Nothing in a scratchpad is deleted here.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (live terminal, uncommitted work, or unresolved session).
